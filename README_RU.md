# SL Guard — защита складских локаций InvenTree

[![PyPI version](https://img.shields.io/pypi/v/inventree-sl-guard?label=PyPI%20version)](https://pypi.org/project/inventree-sl-guard/)
[![PyPI downloads per month](https://img.shields.io/pypi/dm/inventree-sl-guard?label=downloads%2Fmonth)](https://pypistats.org/packages/inventree-sl-guard)

**Версия 0.3.2 beta. Проверена на InvenTree 1.6.1. Не является официальным компонентом InvenTree.**

**Склад — это физическая система, а не произвольное дерево записей в базе данных.** Помещения, ряды, стеллажи и стационарные полки занимают конкретные места в реальном пространстве. Если их цифровая иерархия начинает произвольно меняться, адресная структура перестаёт соответствовать настоящему складу.

**Ошибка в иерархии локаций может нарушить адресную структуру целого участка склада.** Например, если закреплённый стеллаж по ошибке перенести в другую локацию, вместе с ним изменятся цифровые адреса всех вложенных полок и ячеек — хотя физически оборудование останется на месте. Такие изменения должны быть доступны только уполномоченным сотрудникам.

SL Guard помогает предотвратить такие несанкционированные перестановки **для локаций, типы которых администратор отметил как защищённые**. Он ограничивает их перемещение, но не является универсальной проверкой габаритов или физической совместимости вложенных объектов.

**SL Guard закрепляет физический каркас склада в цифровой модели InvenTree.** Администратор выбирает типы стационарных локаций, а плагин не позволяет неуполномоченным пользователям перемещать их, менять уже защищённый тип или обходить запрет переносом родительской локации вместе с защищёнными потомками. При этом уполномоченные сотрудники могут осознанно менять структуру, а обычное движение товаров продолжает работать по штатным правам InvenTree.

**Цифровая схема должна соответствовать реальному складу. Пусть перемещаются товары, а не стеллажи в базе данных.**

[![Support on Ko-fi](https://img.shields.io/badge/Support%20on-Ko--fi-FF5E5B?logo=kofi&logoColor=white)](https://ko-fi.com/sntpartizan)

SL Guard — бесплатный плагин с открытым исходным кодом. Если он оказался полезен, можно [поддержать разработку на Ko-fi](https://ko-fi.com/sntpartizan). Донаты полностью добровольные.

## Возможности

- Выбор защищённых `StockLocationType` по **ID**.
- Первое назначение защищённого типа по стандартным правам пользователя.
- Запрет изменения `parent` и снятия/смены уже защищённого типа для неуполномоченных пользователей.
- Защита при косвенном перемещении (перемещение предка, содержащего защищённую SL).
- Массовая установка типов: полные пути, ID, чекбоксы, поиск с включаемыми полями и Regex, предварительный просмотр, транзакционное применение.
- Текстовый пункт навигации **SL Guard** и компактный виджет **SL Guard** с контурным щитом, цвет которого зависит от темы InvenTree. Оба элемента включаются независимо.
- Установка без изменения файлов ядра на диске.

## Перед установкой: разрешите сторонние плагины

Если InvenTree показывает сообщение **«Сторонние плагины не разрешены для данной установки»**, поддержку плагинов нужно включить **в конфигурации сервера**. Откройте используемый сервером `config.yaml` (расположение зависит от установки; например, `/home/inventree/InvenTree/config/config.yaml`) и укажите:

```yaml
plugins_enabled: true
plugin_noinstall: false
```

Либо задайте переменные окружения серверного процесса:

```env
INVENTREE_PLUGINS_ENABLED=true
INVENTREE_PLUGIN_NOINSTALL=false
```

Не создавайте дублирующиеся ключи YAML; проверьте, что переменные окружения не переопределяют значения файла. **После изменения конфигурации** перезапустите веб-сервис и фоновые процессы InvenTree (для Docker — соответствующие контейнеры). Для установки через интерфейс требуется **учётная запись суперпользователя**. После включения плагинов SL Guard можно установить по одному имени пакета.

## Установка через интерфейс InvenTree (рекомендуется)

**SL Guard доступен на [PyPI](https://pypi.org/project/inventree-sl-guard/).** Теперь для установки через интерфейс InvenTree достаточно указать название пакета. Установка проверена на InvenTree 1.6.1.

1. Сделайте резервную копию базы и настроек; первоначальную установку проверяйте на тестовом InvenTree. Убедитесь, что поддержка сторонних плагинов и их установка включены, как описано выше.
2. Под суперпользователем откройте **Settings → Admin → Plugins → Install Plugin** (Настройки → Администрирование → Плагины → Установить плагин).
3. Заполните поля:

   | Поле | Значение |
   | --- | --- |
   | Название пакета (Package Name) | `inventree-sl-guard` |
   | Ссылка (Source URL) | **Оставить пустой** (установка с PyPI) |
   | Версия | Оставить пустой |
   | Подтверждение установки | Включить |

4. Нажмите **Установить**. InvenTree сам запустит pip в своём окружении Python, зарегистрирует плагин и соберёт статические файлы.
5. В списке плагинов **активируйте SL Guard** (отображается как `SL Guard`). Если потребуется, перезапустите веб-процессы InvenTree и worker, чтобы они загрузили новый код. При старом JavaScript сделайте Ctrl+F5; `manage.py collectplugins` нужен вручную только при проблемах со статикой, с правильным конфигом InvenTree.
6. В настройках SL Guard выберите **ID защищённых типов StockLocationType**, а при необходимости — **ID разрешённых групп**. Панель управления: `/web/plugin/sl-guard/manage` на вашем сервере.
7. Проверьте запрет перемещения под обычным пользователем и разрешение под администратором.

**Виджет дашборда** сам не добавляется. Его нужно выбрать в штатном меню **Дашборд → Добавить виджеты**. Отображение пункта навигации и виджета включается и выключается независимо в настройках SL Guard. Скрытие этих элементов **не отключает защиту**.

### Обновление и установка напрямую из GitHub

Для установки с PyPI откройте **Настройки → Плагины**, нажмите **Update** и укажите пакет `inventree-sl-guard`, оставив **Source URL** и **Version** пустыми. После обновления проверьте версию и работу защиты. При обновлении того же плагина `sl-guard` настройки сохраняются, но их стоит перепроверить.

Для установки непосредственно из GitHub вместо PyPI можно указать ссылку `git+https://github.com/SntPartizan/inventree-sl-guard.git` в поле **Source URL**. Версию оставьте пустой. При обновлении плагина, установленного из GitHub, повторно укажите Git-ссылку: InvenTree 1.6.1 может её не подставить. Для установки зафиксированной версии используйте `git+https://github.com/SntPartizan/inventree-sl-guard.git@v0.3.2`.

### Резервный вариант: установка wheel вручную

Если штатный установщик недоступен, установите скачанный `.whl` в **то же окружение Python**, где работает InvenTree:

```bash
python -m pip install --no-deps --upgrade ./inventree_sl_guard-0.3.2-py3-none-any.whl
```

Затем перезапустите InvenTree и worker, активируйте плагин и при необходимости выполните `manage.py collectplugins`.

Бренд **SL Guard** одинаковый на русском и английском. Панель переведена на оба языка. Идентификаторы нового плагина: пакет `inventree-sl-guard`, отображаемое имя `SL Guard`, slug `sl-guard`.

## Порядок работы

Сначала создайте тип штатными средствами InvenTree. Затем найдите нужные локации в панели, отметьте галочками, выберите тип и проверьте предварительный список **полных путей и ID**. Примените назначение. После этого отметьте тип как защищённый и укажите группы, которым разрешено управление.

Поиск проверяет только **название** по умолчанию. Поиск по полному пути включается отдельным переключателем: если его включить, запрос «Стеллаж» также найдёт все коробки, находящиеся на стеллажах. Regex `Стеллаж|Полка` означает ИЛИ, `^(Стеллаж|Полка)` ищет названия с этих слов.

**Важно:** при ошибке `timeout` нельзя считать, что транзакция отменена. Перезагрузите таблицу и проверьте реальные типы перед повторным применением.

## Проверка прав

| Операция | Обычный пользователь с правом редактирования SL | Superuser / разрешённая группа |
| --- | --- | --- |
| Первичное назначение защищённого типа | Да | Да |
| Снятие / смена уже защищённого типа | Нет | Да |
| Перемещение защищённой SL или её родителя | Нет | Да |
| Переименование / описание | Да | Да |

Действуют дополнительные штатные ограничения InvenTree (роли, владение локацией).

## Ограничения

Этот плагин **не меняет файлы ядра InvenTree**, но использует monkey patch `LocationSerializer.validate()` для штатного перемещения под администратором. Поэтому после обновлений InvenTree требуется тестировать совместимость. Обходными путями остаются прямой SQL, `QuerySet.update()`, отдельные массовые операции дерева и удаление защищённых типов. Для пользовательского сообщения на экране сканирования отдельный *необязательный* скрипт может менять исходник UI InvenTree — не применяйте его без самостоятельного решения и пересборки интерфейса.

Тестирование: `python -m pytest -q tests` и `node --test tests/js/*.test.mjs`. Подробнее: [матрица проверок](docs/test-matrix.md).

Плагин развивается как независимый open-source проект под лицензией MIT. Панель управления переведена на русский и английский; выбор языка происходит автоматически.


## Локализация

В версии **0.3.2** интерфейс панели доступен на английском и русском языке. Язык панели определяется настройкой языка интерфейса InvenTree (`context.locale`), английский используется по умолчанию. Ошибки API переводятся по активному языку Django. Статические поля настроек плагина (названия параметров) пока представлены на английском. См. [подробности](docs/localization.md).
